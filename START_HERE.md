# NAJA HATCH — English Launch Package 1.2

**October 22, 2026. Specifications and development instructions, not a delivered compiler or VSIX.**

## Start or update

For a new project, extract this folder into a dedicated workspace, open it in an authorized coding agent with development tools and give it `prompts/01_INITIAL_AGENT.md`.

For an existing repository, use `prompts/06_AGENT_UPDATE_ENGLISH_PRODUCTIVITY.md`. Merge by identifier, preserving code, state, history and evidence; never overwrite actual progress with the fresh templates in this package. The earlier interactive update prompt remains available as `prompts/05_AGENT_UPDATE_INTERACTIVE.md`.

One agent can perform the mission. With two, one integrator assigns a separate branch/worktree to a contributor/reviewer using prompt 02. Resume with prompt 03 and audit with prompt 04. Do not assume a second agent is running.

## Read first

Read `AGENTS.md`, documents 01–02, roadmap 12 and acceptance 14, then documents 20–23 for the English/productivity revision. Read relevant technical specifications before each task, including 18–19 for native cells. Inspect `planning/requirements.json`, `tasks.json`, `state.json` and the actual handoff.

The scope is **139 mandatory HATCH requirements, 8 future objectives, 38 tasks and 19 release gates**. Counts describe work required, not progress. All fresh-package implementation statuses are not started.

## Founding constraints

NAJA is independent of Python, native, self-hostable and capable of automatic optimization plus explicit authorized hardware control. Python-like syntax retains optional `:(x)` and project aliases. LLVM and the initial seed language are not permanent requirements. Deliver real VS Code tooling, native sessions and productive system/application/data libraries.

All official project material is English. Target at most 25% of comparable Rust and C++ task code on the six approved cases, with separately measured development-time reduction. Never trade away correctness, safety, autonomy or resource limits to achieve a shorter example.

## Authorization boundaries

The implementation mandate includes controlled environment preparation, an authorized **new public GitHub repository**, documentation and development through HATCH acceptance. It does not permit publishing private data, purchases, replacing another repository, opening services to the Internet or bypassing security controls.

HATCH replaces the older ADAM proposals. Do not use an earlier Python-dependent prototype or CPython fallback as the foundation. Reversible defaults can change through reviewed ADRs; agents may not weaken founder requirements.
