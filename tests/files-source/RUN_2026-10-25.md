All 96 emitted programs actually executed. The 441 child commands produced
333 exit-0 results, 50 expected exit-1 results, six exit 103, 11 exit 105,
11 exit 108 and 30 exit 109. No spawn error, timeout or terminating signal
occurred. Every expected runtime failure required exact stdout and English
stderr bytes; a crash or timeout could not satisfy it.

Every before/after inventory around both `check` and `build` matched exactly.
All preexisting private input and foreign-file bytes remained unchanged during
native execution. Expected new outputs matched exact independent sizes and
SHA-256 hashes; no unexpected data file appeared. Case SOURCE/config/input
files lived under the native data inventory, while requested ELF files and
command-capture/inventory JSON lived in its enclosing artifact directory.
The compiler's Windows SOURCE path and each program's Linux working directory
are recorded separately. All user program data paths resolved within the
privately owned fixture cases; no arbitrary outside file mutation was tested.

Binary and UTF-8 roundtrips preserved empty data, all 256 unsigned byte values,
NUL, Unicode scalar width boundaries, compatibility characters and decomposed
text without normalization. All 26 invalid UTF-8 vectors and the invalid file
decode failed with `NJA209`/109. Imported API functions worked in both source
dialects, including header order, multiline/trailing-comma imports, multiple
distinct aliases for one API, Unicode/raw-keyword-lookalike bindings, functions,
parameter shadowing and shared suite/project-alias forms. Duplicate/NFKC-bound
collisions, late/nested/unknown imports, rebinding, local calls, API values,
wrong arity and the original multilingual error location were rejected.

Reads at 16 MiB minus one and exactly 16 MiB succeeded; a larger initial file
failed with the file-limit diagnostic. A generated exact-16-MiB write produced
the expected file hash. The generated 16-MiB-plus-one write failed preflight
without creating output. A conversion view over that same file-size limit
succeeded under the unchanged 64 MiB arena, independently confirming that
the file cap does not restrict UTF-8 conversion values.

ASCII and Unicode paths at exactly 4095 UTF-8 bytes succeeded. Their 4096-byte
controls and embedded NUL paths failed with the distinct frozen diagnostics
before creating any output. Exclusive writes preserved an existing foreign
file and a completed first output; an owned completed output also survived
a later conversion failure. PATH then DATA effects occurred once in order,
and earlier operand failures/short-circuiting suppressed later effects.
The leaf-symlink read was refused, while the private parent-symlink path
followed ordinary OS semantics and succeeded. Neither fixture reached outside
the private case directory.

The first changed-source control altered transferred bytes and was rejected by
the normal output verifier. The second preserved process exit, stdout and file
size but changed output bytes from `abc` to `abd`; the same filesystem hash
verifier caught it. Both controls executed normally before being rejected by
the verifier, so process success alone could not pass these tests.
