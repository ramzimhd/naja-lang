# Bounded new-project scaffolder

The module API is `init_project(&Path) -> Result<InitSummary, String>`. This slice
does not wire a CLI command. The integrator supplies `naja init NEW_DIRECTORY`.
The returned summary contains the exact leaf project name and three relative
created filenames, never an absolute path, user-profile inventory or credentials.

## Contract selected before tests

- The parent must already be an ordinary existing directory. Every existing
  parent component is inspected; symlinks, Windows junctions/reparse points,
  network/device namespaces, alternate streams and `..` traversal reject.
  Windows drive-relative spellings such as `C:project` reject instead of using
  ambient per-drive working directories.
- The leaf must not exist. Empty/nonempty directories, files, links and dangling
  links all reject. The operation does not reuse, replace or merge a directory.
- Input/resolved paths are bounded to 32,768 UTF-8 bytes and 128 components;
  parent components to 255 UTF-8 bytes; leaf/project name to 128 UTF-8 bytes.
  Paths must be valid Unicode. Portable spelling excludes private `.git`,
  reserved filename/device names, controls, trailing dot/space, quotes and
  backslashes inside a component. Windows local disk separators/prefixes work.
- Unicode names and spaces remain data without normalization. Quote, backslash
  and control names reject before writing, rather than risking TOML injection.
  Shell-looking punctuation that is otherwise a valid filename is inert data;
  no shell or other process is invoked.
- Exactly three fixed files are generated, each bounded to 4,096 UTF-8 bytes:
  `naja.toml`, `main.naja`, `test_smoke.naja`. The complete generated manifest
  passes the schema-1 parser, and both source files pass the current shared seed
  checker before the directory is created. Generated bytes are not executed.
- The leaf and each file are created exclusively. Files are flushed with
  `sync_all`; normal completion does not require an automatic run or build.
  A partial I/O failure preserves the owned directory and any output, reports
  failure and requests inspection. There is no recursive rollback or sweeping
  cleanup, and a retry refuses that now-existing target.

The manifest declares schema 1, NAJA edition 2026.1, hosted, entry `main.naja`,
and target `x86_64-unknown-linux-gnu`. There are no dependencies, aliases,
download/install hooks or hidden project logic. Main defines an ordinary native
function returning `6 * 7`, checks the result with `assert` and prints 42. The
smoke source independently defines/calls a small function and asserts basic
native integer/text/length operations. It is a **program-file smoke test**;
there is no test-function discovery, import framework or package resolver claim.

## Filesystem and evidence limits

The checks assume a stable ordinary local project tree, as the explicit alias
loader does. Parent and target identity are rechecked around writes, but these
std filesystem calls are not an atomic confinement mechanism against malicious
concurrent rename/link replacement. Hard links, mount ownership, remote state
and OS permissions are not authenticated. Unix creation requests directory 0700
and file 0600; Windows inherits the parent's ACL. No privilege or ACL changes are
made. File bytes are flushed; universal directory/power-loss durability is not
claimed. Error text reports English operation/error kinds and relative generated
filenames without echoing absolute user paths or localized OS prose.

The scoped tests import the module with `#[path]`. They use only uniquely owned
disposable directories, cover existing-content preservation, invalid/malicious
names, Unicode, path limits, real links/reparse points and generated metadata.
They also call the public seed compiler on both generated sources and inspect
the returned ELF bytes without executing them. A private write-phase test uses
a real exclusive-create collision to check that partial output and foreign
content are retained; it does not claim race-resistant filesystem confinement.
The Windows junction fixture uses the native `cmd.exe` `mklink /J` builtin on
strictly quoted generated paths; the production scaffolder launches no process.
Symlink-capability failures are reported rather than silently skipping coverage.

```text
cargo test --locked --offline -p naja-seed --test scaffold
cargo clippy --locked --offline -p naja-seed --test scaffold -- -D warnings
rustfmt --check --edition 2024 bootstrap/driver/src/scaffold.rs bootstrap/driver/tests/scaffold.rs
```

This is a temporary seed CLI foundation, not full project/package tooling, native
Windows/macOS emission, self-hosting, a distribution or FC1/HATCH acceptance.

On October 25, 2026, the scoped command exited 0 on the Windows development host
with Rust/Cargo 1.97.1: 14 tests passed, 0 failed and 0 ignored, including actual
symlinks and a junction. Scoped Clippy, rustfmt and authored whitespace checks
also exited 0. Unix-specific variants are provided but were not executed by this
Windows run. Generated ELF output was inspected, not executed; actual `init`
CLI wiring and end-to-end build/run/test checks remain integrator work.
