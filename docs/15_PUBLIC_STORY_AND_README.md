# NAJA — Python-like simplicity. Native control. Less application code.

NAJA is an open-source programming language project combining familiar, expressive source code with native execution and explicit low-level control. Python inspires its syntax, not its implementation dependencies.

## Why NAJA exists

NAJA began as a long-held idea: developers should not have to choose between readable code and precise control over the machine. The ambition is to move from everyday applications and data pipelines to systems programming, connected devices, numerical computing and eventually hybrid quantum workflows in one coherent language.

AI-assisted development is helping turn this idea into a concrete engineering effort. Coding agents assist with implementation, tests and documentation. Human direction, transparent review and reproducible evidence remain essential. AI assistance is not a substitute for correctness, security or an honest account of what works.

## The design

NAJA is designed to own its compiler, runtime, standard library and tools without requiring Python. Safe automatic optimization coexists with explicit authorized hardware operations. Optional block-depth markers and project-scoped aliases extend readability without replacing standard forms.

The standard library should make common tasks genuinely shorter, not merely conceal boilerplate. The HATCH productivity target is at least 75% less developer-maintained task code than equivalent idiomatic Rust and C++ implementations on a published benchmark suite. This is a target, not a proven universal result or a promise of four-times-faster development. Code, time, behavior and resource measurements will be published separately.

## HATCH 0.x

The foundational generation targets a usable native compiler, independently rebuildable self-hosted core, productive base libraries for systems/applications/data, native TCP/HTTP APIs, persistent compiled cells, standalone tools and an installable VS Code extension.

Develop interactively using compiled cells, then build a normal native application that does not depend on the interactive controller or session history.

**Current package status: specification only. This launch package does not contain an implemented compiler, working examples or a VSIX.** During real development replace this statement with an evidence-linked status table; do not imply a completed product at repository creation.

## Compatibility and independence

Python syntax, runtime behavior, standard-library coverage and native-extension compatibility are separate goals. Full Python compatibility, universal Rust-level safety and universal C++ performance are not current guarantees. No Python runtime or AI service account is required by the intended standard distribution.
